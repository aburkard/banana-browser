## Tested caching change — finish and ship this

Seven tiny public OpenAI API calls were completed using the local browser’s saved API key. No subscription requests or image generation were involved. Model: GPT-5.6 Luna, low reasoning.

Six calls compared three identical marked screenshot targets using image-first control versus stable instructions/source first, followed by pointer image and coordinates. Both variants were correct on all three targets. Candidate warm calls reused 1,443 input tokens. Total cost including cache writes: control $0.00194325, candidate $0.00107187 (~44.8% lower). Median latency was nearly equal, so don’t promise a general speedup. A separate 10-input-token compatibility request confirmed a short explicit prefix works uncached. Total measured cost for all seven calls: $0.00302312.

The uncommitted production change applies only to **OpenAI API Luna click interpretation**:

- Stable user-message text first with `prompt_cache_breakpoint: {mode:'explicit'}`.
- Root `prompt_cache_options: {mode:'explicit'}` and `prompt_cache_key: 'banana-browser-click-v1'`.
- Pointer image and coordinate instruction follow the boundary.
- Luna cached-input/write pricing added: $0.02/$0.25 per million tokens (ordinary input $0.20, output $1.20).
- Duplicate clicks while a request is pending are ignored.

Gemini, other OpenAI models, subscription transport, and image generation are unchanged. Source data remains in the user role. An independent review found no blocking bugs or secret leaks. **97 app tests and the production build passed** after these changes. Three relay tests passed in the preceding batch; relay code is unchanged.
