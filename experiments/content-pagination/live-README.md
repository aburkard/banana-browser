# Bounded production source-section acceptance

Build with `node experiments/content-pagination/live-build.mjs`. Open `http://127.0.0.1:5178/banana-browser/tmp/pagination-check/index.html` on the existing browser origin. Do not use live.html directly during development: the public bundle deliberately omits Vite live reload. Run `node experiments/content-pagination/live-build.mjs --clean` after collecting results and before building production; public/tmp is Git-ignored but Vite copies public assets into builds.

The page needs the app's saved Gemini and OpenAI keys. It reads them only inside the same browser origin and never prints or stores them in results. Click **Generate first and last sections** once. After both images appear, inspect the displayed last-section target list and pick a visible card. Clicking the last canvas sends the single paid click request. Coordinates are converted to image pixels. There is no automatic coordinate or expected-target guess. Read the returned URL and compare it with the card selected. No resulting URL is fetched.

Calls are bounded to two Gemini 3.1 Flash Image generations (512px, minimal thinking, one candidate, 2,048 output tokens each, 90-second timeout) and one GPT-5.6 Luna click (low reasoning, 512 output tokens, 60-second timeout). Both SDK-call and network-attempt limits are enforced for images; the click fetch is limited to one. No retries occur. Any failure ends the relevant phase. A permanent origin-local `banana-pagination-acceptance-v1` record prevents reruns. It stores only usage, checks, counters and the selected/result coordinates/URL. Failed requests can still be billed.

Locally documented image output estimates: 2 × 747 × $60/M = $0.08964, plus input, text/thinking and Luna click. Charging all 4,096 allowed image-call output tokens at the image rate is $0.24576, plus input and the small click. This is a sub-$1 preflight estimate, not a provider-enforced dollar limit. Aggregate usage/cost comes from production accounting and keeps incomplete estimates marked.

This executes the actual production `sourceSections`, `buildImagePrompt`, `generatePageImage`, `changeSection`, and `interpretClick` methods. It uses 18 synthetic navigation records, split by the production 8,000-character budget into multiple sections. It generates first and last sections; the latter receives the first image for visual continuity. Image/click requests assert exact inclusion of the selected serialized source section. Production red-pointer drawing is retained. Only model limits, diagnostics image logging and transport bounds are overridden. There are no references, source fetches or subscription requests.

Offline checks: `node --test experiments/content-pagination/live.test.mjs`. Tests bundle actual production code and replace the network with in-memory responses. They verify section-source assertions, previous-image continuity, red-pointer drawing, model/output limits, three-call bound, duplicate controls, sanitized results and error stopping. They make no paid requests.

Limitations: this is a one-pair synthetic block-format screen. It does not establish complete on-image text retention, all 18 card visibility, real TVmaze fidelity, history UI restoration or general click accuracy. The harness manually seeds initial state, then uses production section changing. The full source text is intentionally longer than an image can display; inspect that the expected card labels for each section are legible and no other section's cards intrude. An exact source target result does not prove the model picked the user's intended card without visual comparison.
